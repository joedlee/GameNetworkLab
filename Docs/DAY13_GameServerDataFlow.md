# DAY 13 - 게임 서버 데이터 흐름

## 코인 게임 처리 책임

| 상황 | 즉시 처리 담당 | 저장 담당 | 운영 기록 |
| :--- | :--- | :--- | :--- |
| Player가 코인에 닿음 | Game Server가 거리·중복 확인 | 게임 종료 또는 저장 시 DB에 Score 기록 | CoinCollected 횟수 |
| Client 접속 실패 | 접속 모듈이 실패 반환 | 저장하지 않음 | 실패 시각·오류 코드 |
| 새 버전 배포 | Patch 서버가 버전 비교 | 파일 목록·버전 정보 관리 | 적용 성공·실패 수 |

## Score 저장 구조

```text
PlayerId
Score
LastSavedAt
```

- `PlayerId`: 어떤 플레이어의 데이터인지 구분한다.
- `Score`: 저장할 현재 점수다.
- `LastSavedAt`: 마지막 저장 시각이다.
- `LastSavedAt`은 서버와 DB 사이에서 형식이 흔들리지 않도록 ISO 8601 문자열 형식으로 저장한다.
  - 예: `2026-10-19T12:30:00+09:00`

## 실시간 이동 위치를 매 프레임 DB에 저장하지 않는 이유

1. 플레이어 이동은 매우 자주 변경되므로 매 프레임 DB에 기록하면 불필요한 쓰기 요청이 폭증한다.
2. 실시간 위치는 Game Server가 메모리와 네트워크 동기화로 관리하면 충분하며, DB는 점수·보상·진행도처럼 오래 보관할 데이터에 집중하는 것이 적절하다.

## 접속 리포트

Host 시작, Client 연결, Client 종료 상황에서는 최소한 시간, 이벤트 이름, Client 식별값을 남긴다.

| 상황 | 시간 | 이벤트 이름 | Client 식별값 | 예시 로그 |
| :--- | :--- | :--- | :--- | :--- |
| Host 시작 | ISO 8601 시각 | `HostStarted` | Host의 ClientId | `2026-10-19T12:40:00+09:00 HostStarted ClientId=0` |
| Client 연결 | ISO 8601 시각 | `ClientConnected` | 접속한 ClientId | `2026-10-19T12:40:12+09:00 ClientConnected ClientId=1` |
| Client 종료 | ISO 8601 시각 | `ClientDisconnected` | 종료한 ClientId | `2026-10-19T12:41:03+09:00 ClientDisconnected ClientId=1` |

이 로그를 남기면 운영자는 누가 언제 접속하고 종료했는지 확인할 수 있고,
접속 실패나 비정상 종료가 발생했을 때 원인을 추적할 수 있다.

## 오늘의 정리

게임 서버 응용 프로그램은 실시간 동기화만 담당하는 것이 아니다.

- Game Server는 이동, 충돌, 코인 획득 같은 즉시 판정을 담당한다.
- DB는 점수, 보상, 진행도처럼 오래 보관할 데이터를 담당한다.
- Reporting은 접속, 종료, 오류, 게임 결과를 운영자가 추적할 수 있게 한다.
- Patch 시스템은 클라이언트 버전과 최신 버전을 비교하고 필요한 파일을 배포한다.
- 각 시스템의 책임을 분리하면 실시간 처리와 영구 저장이 서로 불필요하게 얽히는 것을 줄일 수 있다.
