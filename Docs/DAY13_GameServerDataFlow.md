# DAY 13 - 게임 서버 데이터 흐름

## 코인 게임 처리 책임

| 상황 | 즉시 처리 담당 | 저장 담당 | 운영 기록 |
| :--- | :--- | :--- | :--- |
| Player가 코인에 닿음 | Game Server가 거리·중복 확인 | 게임 종료 또는 저장 시 DB에 Score 기록 | CoinCollected 횟수 |
| Client 접속 실패 | 접속 모듈이 실패 반환 | 저장하지 않음 | 실패 시각·오류 코드 |
| 새 버전 배포 | Patch 서버가 버전 비교 | 파일 목록·버전 정보 관리 | 적용 성공·실패 수 |

## Score 저장 구조

```text
PlayerId
Score
LastSavedAt
```

- `PlayerId`: 어떤 플레이어의 데이터인지 구분한다.
- `Score`: 저장할 현재 점수다.
- `LastSavedAt`: 마지막 저장 시각이다.
- `LastSavedAt`은 서버와 DB 사이에서 형식이 흔들리지 않도록 ISO 8601 문자열 형식으로 저장한다.
  - 예: `2026-10-19T12:30:00+09:00`

## 실시간 이동 위치를 매 프레임 DB에 저장하지 않는 이유

1. 플레이어 이동은 매우 자주 변경되므로 매 프레임 DB에 기록하면 불필요한 쓰기 요청이 폭증한다.
2. 실시간 위치는 Game Server가 메모리와 네트워크 동기화로 관리하면 충분하며, DB는 점수·보상·진행도처럼 오래 보관할 데이터에 집중하는 것이 적절하다.
